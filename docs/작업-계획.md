# 작업 계획: NovelAI 기능 확장

1.0.0 이후 작업 계획입니다. 지금 앱은 "레퍼런스 인셋(인페인트)으로 감정 세트 만들기" 한 가지만 합니다.
여기에 NovelAI가 제공하는 다른 생성 방식과 편의 기능을 붙입니다. 로컬 AI 모델(업스케일러, 배경 제거
모델 등)은 쓰지 않고 NovelAI 기능만으로 해결합니다.

작업 규칙은 [AGENTS.md](../AGENTS.md)에 있습니다. 특히 **사용자가 말하기 전에는 GitHub에 푸시하지
않습니다.**

## 사용자가 정한 것

- 감정 모드(지금의 감정 갤러리 구조)와 **자유 생성 화면**을 따로 둡니다.
- 0단계에서 유료일 수 있는 기능을 기능마다 한 장씩 시험해도 됩니다.
- 릴리스는 여러 단계를 묶어서 합니다. 버전을 올리고 빌드까지는 해도 되지만, 커밋 푸시·태그·GitHub
  릴리스는 사용자가 요청할 때만 합니다. 사용자는 로컬에서 직접 테스트한 뒤 올립니다.

## 실험 도구

NovelAI 실제 호출은 로컬 실험 스크립트로 확인합니다. 앱의 프롬프트 합성·요청 생성·호출 코드를 그대로
쓰는 Electron 스크립트이고, 파일은 `legacy/tools/nai-exp/`에 있습니다(git에 올라가지 않는 폴더).

- `entry.ts`: 실험 본체. 앱의 토큰 보관 파일 두 개(`%APPDATA%\NAI RICE\Local State`,
  `novelai-token.vault`)를 임시 userData로 복사해 토큰을 읽고, 끝나면 사본을 지웁니다.
  - Opus(tier 3)가 아니면 중단합니다.
  - 생성마다 Anlas를 다시 조회해 **줄어들면 바로 중단**합니다.
  - 1024×1024 초과나 28스텝 초과 조건은 시작 전에 막습니다.
- 계획 파일(JSON): `referenceImage`, `presetFile`(프리셋 내보내기 파일), `baseLayout`, `characterId`,
  `promptSetId`, `emotionSetId`, `emotionName`, `seeds`, `conditions[{name, commonPositive, layout, model,
generation}]`, `out`. 예시는 `planVS.json`, `planI3.json`, 생성 스크립트는 `mkv5.cjs`, `mkI.cjs`입니다.
- 비교표: `sheet3.cjs <결과 폴더> <참고 그림> <seed,seed,seed> <조건,조건,...>` (환경 변수 `EXP_PROJECT`).

실행 방법(Git Bash):

```sh
P=C:/Users/bobow/Desktop/risu/reference-inpaint-desk
cd <스크립트를 둔 임시 폴더>
$P/node_modules/.bin/esbuild entry.ts --bundle --platform=node --format=cjs \
  --external:electron --alias:P=$P --outfile=entry.cjs
unset ELECTRON_RUN_AS_NODE
EXP_PROJECT=$P EXP_PLAN=<계획.json> $P/node_modules/electron/dist/electron.exe entry.cjs
```

- 결과 폴더는 `ForTest/` 아래에 둡니다(git 무시).
- 2단계에서 생성 작업 구조를 바꾸면 `entry.ts`도 새 함수에 맞게 고쳐야 합니다.
- 0단계처럼 인페인트가 아닌 요청을 보낼 때는 `entry.ts`를 복사해 요청 부분만 바꾼 별도 스크립트를 씁니다.
  유료일 수 있는 기능은 Anlas 중단 검사가 사후 검사라는 점을 기억하고 **한 장씩만** 보냅니다.

## 0단계: NovelAI API·비용 확인

NovelAI 이미지 API는 공식 문서가 없습니다. NovelAI 웹이 보내는 요청 형식을 기준으로 맞춥니다(커뮤니티
구현체, 예를 들어 ComfyUI_NAIDGenerator 같은 프로젝트의 요청 코드를 참고할 수 있습니다). 기능마다 한 번씩
요청해 다음을 기록합니다.

| 기능            | 확인할 것                                                                                                                             |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 일반 생성       | `action: 'generate'`, 인페인트가 아닌 모델 ID(V5 Full·Curated, V4.5 Full·Curated, V4, V3), 응답 형식                                  |
| i2i             | `action: 'img2img'`의 `strength`·`noise`, 입력 이미지와 다른 크기로 요청할 때 동작, V5 할당량 소모가 두 배인지                        |
| 디렉터 툴       | 엔드포인트(`/ai/augment-image`로 알려짐), `req_type`별 옵션(Emotion의 감정 이름·강도·프롬프트, 배경 제거, Declutter), 크기 제한, 비용 |
| 캐릭터 레퍼런스 | Precise Reference 요청 필드, 비용, V5 모델로 요청하면 어떻게 되는지                                                                   |
| 바이브 트랜스퍼 | 바이브 인코딩 요청과 비용, 생성 요청에 넣는 필드, 인코딩 결과 재사용                                                                  |
| 업스케일        | 비용과 크기 제한(4단계의 i2i 우회와 비교용)                                                                                           |
| V5 투명 배경    | `transparent background` 태그가 인페인트·i2i 결과에도 알파 채널을 주는지, 지금 결과 자르기가 알파를 유지하는지                        |
| 비용 계산식     | NovelAI 웹의 Anlas 계산식(크기, 스텝, 장수, i2i strength, Opus 무료 조건), V5 할당량 소모 비율                                        |

- 결과는 이 문서 아래 "0단계 결과" 절에 요청 예시(토큰 제외), 응답 형식, 실제 소모량으로 적습니다.
- 결과 이미지는 `ForTest/`에 둡니다.

### 0단계 결과

시험 스크립트는 `legacy/tools/nai-exp/probe.ts`(계획 파일 `planS0*.json`, 실행 `run-probe.sh <계획>`)입니다.
앱의 인페인트 요청 본문에서 출발해 `action`, `model`, 이미지 필드만 바꿔 보냅니다. 요청마다 요청 모양(이미지는
해시), 응답 형식, Anlas·V5 할당량 변화를 `ForTest/stage0-*/<이름>.json`에 남깁니다.

#### A. 무료 범위 (2026-10-09, `ForTest/stage0-a`)

Opus, 832×1216(i2i 한 건은 1024×1024), 28스텝, 1장, seed 1234567. 14건 모두 200, **Anlas 차감 0**. V5 할당량
표시는 시작 10%에서 끝까지 10%로 변하지 않았습니다(V5 요청 6건).

- **응답 형식:** 모든 생성 종류가 지금 인페인트와 같습니다. `binary/octet-stream` ZIP 안에 `image_0.png` 한 장,
  RGBA PNG입니다. 일반 결과도 알파 채널이 있지만 최솟값이 243~254입니다(NovelAI가 알파에 정보를 숨기는 것으로
  보임). 투명 여부는 "알파 최솟값이 0인가"로 판단해야 합니다.
- **일반 생성 모델 ID:** `nai-diffusion-5-full`, `nai-diffusion-5-curated`, `nai-diffusion-4-5-full`,
  `nai-diffusion-4-5-curated`, `nai-diffusion-4-full`, `nai-diffusion-4-curated-preview`, `nai-diffusion-3`이 모두
  됩니다. V5 Curated는 일반 생성만 있고 인페인트 모델은 앱 목록에 없습니다.
- **일반 생성 요청:** 인페인트 본문에서 `action: 'generate'`, 인페인트가 아닌 모델 ID로 바꾸고 `image`, `mask`,
  `strength`, `noise`, `img2img`, `inpaintImg2ImgStrength`, `add_original_image`, `extra_noise_seed`를 빼면
  됩니다. V5는 지금처럼 최상위에 `use_new_shared_trial: true`를 둡니다.
- **i2i 요청:** `action: 'img2img'`, `image`, `strength`, `noise`, `extra_noise_seed`(= seed). V4 이상은
  `img2img: { strength, noise, begin_from_sigma: null, extra_noise_seed, color_correct: true }`도 같은 값으로
  넣었고 그대로 받아들여졌습니다. `mask`, `inpaintImg2ImgStrength`, `add_original_image`는 뺐습니다.
- **i2i 크기:** 서버는 입력 이미지를 요청한 `width`×`height`로 **비율을 무시하고 늘립니다**. 832×1216 입력을
  1024×1024로 요청하면 얼굴이 옆으로 퍼진 결과가 나옵니다. 앱이 보내기 전에 목표 비율에 맞춰 자르거나 여백을
  넣어야 합니다. 작은 입력(416×608)을 832×1216으로 요청하는 것은 문제없고 차감도 없습니다.
- **업스케일 우회:** 416×608 → 832×1216, strength 0.4에서 얼굴과 구도는 유지되고, 단순 확대보다 선과 눈이
  선명하게 다시 그려집니다. 머리카락 그늘 색이 조금 바뀝니다. 4단계 기본값 실험은 0.3~0.5에서 합니다.
- **V5 투명 배경:** `transparent background` 태그로
  - 일반 생성: 배경이 실제로 투명(알파 0)합니다.
  - 인페인트(마스크 전체): 투명합니다. 결과를 앱의 자르기(`cropWithMetadata`의 sharp `extract`)에 넣어도
    알파가 유지됩니다.
  - i2i(불투명 입력, strength 0.5): 투명해지지 않습니다. 입력 배경을 그대로 따라갑니다.
- **V5 할당량 소모:** 6건으로는 표시가 1%도 움직이지 않아, i2i가 두 배 드는지 판단하지 못했습니다. 표시 값이
  남은 양인지 쓴 양인지도 이 결과만으로는 알 수 없습니다.

#### B. 디렉터 툴 (2026-10-09, `ForTest/stage0-b`)

`POST https://image.novelai.net/ai/augment-image`, 본문 `{ req_type, width, height, image, prompt?, defry? }`.
입력은 832×1216 V4.5 결과입니다. 응답은 생성과 같은 ZIP이고, 결과 PNG의 `Comment`에는 `req_type`(Emotion은
`prompt`, `defry`도)만 들어 있습니다. `Source`는 없습니다.

| req_type     | 실제 차감    | 응답                                                    |
| ------------ | ------------ | ------------------------------------------------------- |
| `emotion`    | 0 (2회 모두) | RGB PNG 1장, 같은 크기. `prompt: "happy;;"`, `defry: 0` |
| `bg-removal` | **65 Anlas** | RGBA PNG **3장**(`image_0~2`), 모두 배경이 투명(알파 0) |

- 배경 제거는 Opus여도 무료가 아닙니다. 832×1216 한 번에 65 Anlas입니다. 5단계에서 실행 전 확인 창이 꼭
  필요합니다.
- 배경 제거의 세 장은 거의 같고 입가 같은 작은 부분만 다릅니다. 각각이 무엇인지는 아직 모릅니다.
- Emotion `happy`, `defry: 0`은 이미 웃는 입력에서 변화가 거의 없었습니다. 표정 변화가 큰 감정으로 다시 봐야
  합니다.
- 차감이 허용치(30)를 넘어 여기서 멈췄습니다. 나머지는 C에서 보냈습니다.

#### C. 나머지 디렉터 툴, 캐릭터 레퍼런스, 바이브, 업스케일, 계산식 (2026-10-09, `ForTest/stage0-c`)

| 시험                                  | 실제 차감 | 결과                                                                |
| ------------------------------------- | --------- | ------------------------------------------------------------------- |
| `declutter`                           | 0         | RGB 1장. 깨끗한 입력이라 변화가 거의 없음                           |
| `lineart`                             | 0         | RGB 1장. 흑백 선화                                                  |
| `sketch`                              | 0         | RGB 1장. 연필 스케치                                                |
| `colorize` (`prompt: ""`, `defry: 0`) | 0         | RGB 1장. 선화에 색을 새로 칠함. 프롬프트가 없으면 머리·눈 색이 바뀜 |
| 캐릭터 레퍼런스, V4.5                 | **5**     | 참고 그림의 머리·옷이 잘 옮겨짐. `Source`는 V4.5                    |
| 캐릭터 레퍼런스, V5                   | 0         | **500 오류**(5번 시도 모두). V4.5로 바뀌지 않고 실패함              |
| 바이브 인코딩, V4.5                   | **2**     | `application/binary` 49,024바이트(ZIP 아님)                         |
| 바이브 사용, V4.5 일반 생성           | 0         | 정상. 인코딩 결과를 base64로 `reference_image_multiple`에 넣음      |
| 바이브 + 인페인트, V4.5               | 0         | 정상(`Source`는 V4.5 인페인트 모델). 인셋 + 바이브 조합은 가능      |
| 바이브 사용, V5 (V4.5 인코딩)         | 0         | **500 오류**(5번 시도 모두)                                         |
| 업스케일 `api.novelai.net/ai/upscale` | 0         | **404** `Cannot POST /ai/upscale`. 주소가 바뀐 것으로 보임          |
| 일반 생성 512×512, 29스텝             | **6**     | 커뮤니티 계산식 값(6)과 같음                                        |

- **디렉터 툴 비용:** 배경 제거만 유료(832×1216에 65)이고, 나머지 다섯 가지는 Opus에서 832×1216까지 무료입니다.
  응답의 PNG 수는 배경 제거만 3장, 나머지는 1장입니다. 결과는 RGB라 알파가 없습니다.
- **캐릭터 레퍼런스:** 요청 필드는 `director_reference_images`(1024×1536 등 정해진 캔버스에 검은 여백),
  `director_reference_descriptions`(`base_caption: "character&style"` 또는 `"character"`),
  `director_reference_information_extracted: [1]`, `director_reference_strength_values: [1]`,
  `director_reference_secondary_strength_values: [1 - fidelity]`. 무료 조건 안에서도 한 번에 5 Anlas가
  듭니다. V5는 이 형식으로는 안 되므로 6단계에서 V4.5 전용으로 둡니다.
- **바이브:** `POST https://image.novelai.net/ai/encode-vibe`, 본문
  `{ image, information_extracted, model }`. 인코딩 한 번에 2 Anlas이고, 인코딩 결과는 같은 모델에서 다시
  써도 추가 차감이 없습니다. 생성 요청에는 `reference_image_multiple: [인코딩 결과 base64]`,
  `reference_strength_multiple`, `normalize_reference_strength_multiple: true`를 넣었습니다. V5에서는 V4.5
  인코딩으로 500이 났습니다.
- **계산식:** NekoAI-JS의 `calculateCost`를 기준으로 삼습니다. 512×512·29스텝 6 Anlas가 맞았고, 캐릭터
  레퍼런스 +5, 바이브 인코딩 2도 알려진 값과 같습니다. 1-3에서 이 식으로 예상 비용을 계산합니다.
  - 해상도 `r = max(w×h, 65536)`. 832×1216 < r ≤ 1024×1024이면 r = 832×1216.
  - 장당 `ceil(2.951823174884865e-6 × r + 5.753298233447344e-7 × r × steps)`. i2i는 여기에 strength를
    곱해 올림하고, 최소 2.
  - Opus이고 steps ≤ 28이며 r ≤ 1024×1024이면 한 장 무료. 캐릭터 레퍼런스가 있으면 +5.
- 500 오류를 다시 시도한 요청에서는 차감이 없었습니다.

#### D. 업스케일 주소, Emotion 표정, V5 할당량 (2026-10-09, `ForTest/stage0-d`)

- **업스케일:** `image.novelai.net/ai/upscale`은 주소는 있지만 400 `Validation error: model  doesn't exist`로,
  본문에 `model`이 필요합니다. 어떤 값을 넣는지는 확인하지 못했습니다. 4단계 i2i 우회와 비교하려던 것이라
  필요해지면 웹 요청을 확인해 다시 시험합니다.
- **Emotion:** 모두 0 Anlas. `angry`, `sad`는 얼굴만 바뀌고 머리·옷·포즈·배경은 그대로입니다(5단계 감정 세트에
  적합). `defry: 3`(약하게)도 눈물은 남고 표정이 조금 덜할 뿐이라, 강도 차이는 크지 않습니다.
- **V5 할당량:** 원본 값은 `{"percent":10,"isNegative":false,"timeUntilNextPercent":6048}`입니다. 앱은
  `percent`를 남은 양으로 보여 줍니다. 0단계의 V5 요청(일반 생성, i2i, 인페인트) 9건 동안 10%에서 줄지
  않았습니다. 무료 조건 안의 V5 생성이 이 할당량을 쓰지 않는지, 단위가 커서 안 보이는지는 아직 모릅니다.
  1-3의 "할당량 약 n%" 표시는 근거가 생길 때까지 넣지 않습니다.

#### 0단계 정리

- 0단계에서 쓴 Anlas: 78(배경 제거 65, 캐릭터 레퍼런스 5, 바이브 인코딩 2, 계산식 검증 6).
- 이후 단계에 반영할 것
  - 1-3: 위 계산식으로 예상 Anlas. 배경 제거 비용은 식이 없으므로 832×1216 기준 실측값(65)만 기록해 두고,
    크기별 비용은 5단계에서 확인합니다.
  - 3단계: 일반 생성 모델 목록에 V5 Curated 추가. 인페인트 모델은 V5 Curated가 없습니다.
  - 4단계: i2i는 앱이 입력을 목표 비율로 맞춰서 보냅니다. 업스케일 우회 strength는 0.3~0.5에서 정합니다.
  - 5단계: 배경 제거만 유료이고 결과가 3장입니다. Emotion은 무료이고 감정 세트에 바로 쓸 수 있습니다.
  - 6단계: 캐릭터 레퍼런스(+5)와 바이브는 V4.5 전용입니다(V5는 500). 인셋 + 바이브는 됩니다. 캐릭터
    레퍼런스와 바이브를 함께 쓸 수 있는지는 확인하지 않았습니다(커뮤니티 구현은 함께 쓸 수 없다고 봄).
- 남은 질문: 업스케일의 `model` 값, V5 할당량 소모 방식(i2i가 두 배인지 포함).

## 1단계: 편의 기능

기존 구조 안에서 끝나는 작업입니다.

### 1-1. 사이드바 섹션 접기

- 사이드바의 「작업」, 「라이브러리」 제목을 누르면 그 카드가 접힙니다. 다시 누르면 펼칩니다.
- 접힌 상태는 앱 설정(UI 상태)에 저장해 다시 켜도 유지합니다.
- 둘 다 접으면 남는 공간만큼 작업 화면·라이브러리 화면이 넓어집니다.
- 기존 사이드바 전체 접기(Ctrl+B)는 그대로 둡니다.
- 관련 파일: `src/renderer/components/Sidebar.tsx`, `src/renderer/store.ts`, 스타일.

### 1-2. 인페인트 마스크 비우기

- 인페인트 편집 화면의 마스크 도구(`src/renderer/components/ReferenceCanvas.tsx`)에 "생성 마스크 모두
  지우기" 버튼을 넣습니다. 실행 취소(Ctrl+Z)로 되돌릴 수 있어야 합니다.
- 생성 마스크가 비면 지금처럼 "생성 영역이 비어 있습니다" 경고가 뜨고 생성이 막혀야 합니다.

### 1-3. 예상 Anlas 표시

- `NaiCost.ts`에 예상 비용 계산을 넣습니다(0단계에서 확인한 계산식). 입력: 모델, 크기, 스텝, 장수, 생성
  종류(i2i면 strength), 구독 등급, V5 할당량.
- 표시할 곳:
  - 작업 화면 생성 버튼 옆: "예상 0 Anlas (무료)", "예상 약 34 Anlas". V5면 "할당량 약 n%".
  - Anlas 확인 창(`confirmAnlasUse`): 이유 목록과 함께 예상 합계.
  - 큐의 작업 항목: 예상과 실제(`anlasSpent`).
- 테스트: 계산식 단위 테스트. 실제 차감량과 다를 수 있으므로 화면에는 항상 "예상"이라고 씁니다.

## 2단계: 생성 작업 구조 바꾸기

화면 변화 없는 내부 공사입니다. 이 단계가 끝나도 앱 동작은 1단계 후와 같아야 합니다.

- 생성 작업에 종류를 붙입니다: `kind: 'inpaint' | 'txt2img' | 'img2img' | 'augment'`.
  - `inpaint`: 지금 필드 그대로(마스크, `outputRect`, 레퍼런스).
  - `txt2img`: 크기와 프롬프트만.
  - `img2img`: 원본 이미지 경로, strength, noise, 목표 크기.
  - `augment`: 원본 이미지 경로, 디렉터 툴 종류와 옵션.
  - 원본 이미지가 이전 생성 결과면 그 기록 ID(`sourceRecordId`)를 남깁니다.
- 요청 생성 함수를 종류별로 나눕니다. 공통 부분(V4 프롬프트 구조, 태그 힌트, 샘플러)은 함께 씁니다.
- `GenerationRequests`의 재검증 스키마를 종류별로 나눕니다.
- `GenerationOutput`은 `inpaint`만 자르고, 나머지는 받은 이미지를 그대로 저장합니다.
- `GenerationRecord`에 `kind`, `sourceRecordId`, `anlasEstimate`를 추가합니다.
- 모델 목록을 용도별로 나눕니다(인페인트용·일반용). 생성 설정의 모델 선택은 모드에 맞는 목록만 보여 줍니다.
- **호환:** 기존 `generations.json`, 큐 파일, 내보낸 JSON 백업은 `kind`가 없으면 `inpaint`로 읽습니다.
  zod 스키마의 기본값으로 처리하고, 옛 데이터를 읽는 테스트를 추가합니다.
- 완료 기준: 기존 테스트가 모두 통과하고, 옛 데이터 호환 테스트가 있습니다.

## 3단계: 일반 생성과 자유 생성 화면

### 3-1. 모드 버튼

- 작업 화면 위에 **[레퍼런스 생성] [일반 생성]** 버튼을 둡니다. 작업마다 모드를 저장합니다
  (`Project.mode`, 기본값 `reference`).
- **레퍼런스 생성:** 지금의 인셋(인페인트) 방식입니다. 6단계에서 캐릭터 레퍼런스·바이브가 이 모드에
  들어옵니다.
- **일반 생성:** 인페인트 없이 생성 설정 + 캐릭터 + 감정 모음으로 txt2img를 합니다. 작업 구성 막대에서
  인페인트 칸을 숨기고, 해상도는 생성 설정에서 고릅니다(무료 해상도 프리셋 + 직접 입력).
- 감정 갤러리, 대표 이미지, 감정 상세, 내보내기는 두 모드가 같이 씁니다.

### 3-2. 자유 생성 화면

감정 구조 없이 프롬프트만으로 여러 장 뽑는 화면입니다. 사용자가 감정 모드와 따로 두기로 했습니다.

- 사이드바에 「자유 생성」 항목을 따로 둡니다(작업 목록과 구분).
- 화면 구성: 생성 설정 선택, 캐릭터 선택(선택 사항), 프롬프트 입력, 해상도, 장수, 생성 버튼, 결과 격자.
- 결과는 감정이 아니라 생성 순서로 쌓입니다. 결과마다 다시 생성(같은 seed), 프롬프트 복원, 생성 정보,
  삭제, 다른 이름으로 저장, 그리고 4·5단계가 붙으면 i2i·디렉터 툴로 보내기를 제공합니다.
- 저장 위치: 작업 폴더 안의 별도 폴더(예: `free/<세션 또는 날짜>/`). 결과 기록 형식은 `GenerationRecord`를
  재사용하고 `emotionId` 대신 비워 둡니다. 정확한 저장 구조는 2단계 결과를 보고 정합니다.
- 생성 방식은 txt2img 기본, 4단계 이후 i2i도 고를 수 있게 합니다.

## 4단계: i2i와 업스케일 우회

### 4-1. i2i 모드

- 이미지 한 장과 strength를 정하고 i2i로 생성합니다. 감정 모드(감정마다 i2i)와 자유 생성 화면 모두에서
  씁니다.

### 4-2. 결과를 i2i로 보내기 (업스케일 우회)

커뮤니티 댓글에서 나온 방법입니다: 크롭된 결과를 832×1216 같은 큰 크기로 늘려 i2i로 다시 그리면 무료
범위 안에서 해상도를 올릴 수 있습니다(V5는 할당량이 두 배 든다고 함).

- 감정 상세, 갤러리 우클릭 메뉴, 자유 생성 결과에 "i2i로 보내기"를 넣습니다.
- 대화 상자 값: 목표 크기(무료 해상도 프리셋, 원본 비율에 가장 가까운 것을 기본 선택), strength, 프롬프트
  (원래 프롬프트 재사용 기본), 생성 장수, 예상 Anlas·할당량.
- 결과는 같은 감정(또는 같은 자유 생성 세션)에 새 결과로 쌓이고, `sourceRecordId`로 원본을 표시합니다.
- "선택한 감정의 대표 이미지 모두 i2i로" 일괄 실행을 넣습니다.
- 무료 범위 실험으로 strength 기본값을 정합니다(그림체·얼굴 유지와 선명도의 균형, 0.3~0.5 사이 예상).

## 5단계: 디렉터 툴

- 결과 하나에 툴을 적용합니다: **Emotion, 배경 제거, Declutter**를 주요 메뉴로, Line Art·Sketch·Colorize는
  하위 메뉴로 둡니다.
- 결과는 새 결과로 저장하고 `sourceRecordId`를 남깁니다.
- **Emotion 툴로 감정 세트 만들기:** 대표 이미지 한 장(중립)을 골라, 감정 모음의 감정마다 Emotion 툴을
  돌립니다. 몸·옷·포즈가 같은 세트가 나옵니다.
  - 감정 모음의 감정 항목에 Emotion 툴용 값(툴이 받는 감정 이름, 강도)을 선택 사항으로 추가합니다.
  - NovelAI 문서: 정면을 보는 중립 표정의 캐릭터 한 명일 때 가장 잘 됩니다.
- 실행 전에 항상 예상 비용을 보여 줍니다(0단계 결과로 결정).

## 6단계: 캐릭터 레퍼런스·바이브 트랜스퍼

- 레퍼런스 생성 모드 안에 방식 선택을 둡니다: **인셋(지금 방식) / 캐릭터 레퍼런스 / 바이브 / 인셋 +
  바이브**(조합 가능 여부는 0단계에서 확인).
- 캐릭터 레퍼런스·바이브는 V4.5 전용으로 알려져 있습니다(V5로 요청하면 V4.5로 생성된다는 보고). 화면에
  분명히 표시합니다.
- 바이브는 인코딩 결과를 저장해 두고 재사용해 인코딩 비용을 한 번만 냅니다.
- 라이브러리의 「인페인트」 항목을 "참고 이미지" 개념으로 넓혀, 같은 그림을 인셋·캐릭터 레퍼런스·바이브
  어디서든 쓰게 합니다. 이름 변경과 데이터 이전은 2단계 호환 방식과 같이 처리합니다.

## 단계마다 할 일

1. 코드 변경과 테스트(`npm test`, `npm run typecheck`, `npm run lint`)를 통과시킵니다.
2. 실제 NovelAI 호출이 필요한 부분은 실험 도구로 무료 범위에서 확인합니다.
3. 이 문서의 진행 표와 결과를 갱신합니다.
4. 로컬 커밋까지만 합니다. 푸시는 사용자 요청이 있을 때만 합니다.
5. 사용자가 릴리스를 요청하면: 버전 올리기 → `CHANGELOG.md` 맨 위 절 작성 → `npm run package:win` →
   사용자 확인 → 사용자가 푸시·릴리스를 요청하면 진행([개발 가이드의 릴리스 절](개발-가이드.md) 참고).
