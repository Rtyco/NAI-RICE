# 작업 계획: NovelAI 기능 확장

1.0.0 이후 작업의 개요입니다. 1.0.0 앱은 "레퍼런스 인셋(인페인트)으로 감정 세트 만들기" 한 가지만 합니다.
여기에 NovelAI가 제공하는 다른 생성 방식과 편의 기능을 붙입니다. 로컬 AI 모델(업스케일러, 배경 제거 모델
등)은 쓰지 않고 NovelAI 기능만으로 해결합니다.

**읽는 법:** 이 파일만 먼저 읽고, 진행할 단계의 파일 하나만 엽니다. 단계 파일에는 그 단계에 필요한 0단계
실측 결과와 현재 구조가 들어 있습니다. 끝난 단계 파일은 그 기능을 고칠 때만 읽습니다.

## 사용자가 정한 것

- 감정 모드(지금의 감정 갤러리 구조)와 **자유 생성 화면**을 따로 둡니다.
- 유료일 수 있는 기능은 허락을 받고 기능마다 한 장씩 시험합니다.
- 릴리스는 여러 단계를 묶어서 합니다. 버전은 사용자가 정합니다. 커밋 푸시·태그·GitHub 릴리스는 사용자가
  요청할 때만 합니다. 사용자는 로컬에서 직접 테스트한 뒤 올립니다.

## 단계 밖에서 한 작업 (2단계 이후, 2026-10-09)

- **리팩터링:** 생성 흐름의 중복 제거. 큐 재시도·취소·일시정지와 provider 요청 테스트를 먼저 만들어 동작이
  같음을 확인했습니다.
- **결과가 두 장으로 보이던 버그:** 개발 모드의 React StrictMode가 `initialize()`를 두 번 실행해 메인 프로세스
  이벤트 구독이 두 번 걸렸습니다. 구독 해제, 초기화 한 번, 기록 ID 중복 제거로 고쳤습니다.
- **주석 정리:** 코드만 읽어서 알 수 없는 것만 남기고, 규칙을 [AGENTS.md](../AGENTS.md)의 "주석"에
  적었습니다.
- **참고 영역 드래그 렉:** 마우스를 움직일 때마다 마스크 전체를 PNG로 바꾸던(약 30ms) 것을 놓을 때 한 번만
  하게 했습니다. 처음에는 영역 반영도 rAF로 미뤘는데 한 프레임 늦어 딱딱하다는 의견이 있어 되돌렸습니다
  (이동→다시 그리기: 1.0.0 12ms, 지금 10ms).
- **작업 화면 카드:** 카드 비율을 참고 이미지의 출력 영역 대신 3:4로 고정하고, 툴바에서 한 줄 카드 수를
  3~7개로 고릅니다(기본 6, `localStorage`의 `gallery-columns`). 3:4보다 넓은 결과는 위쪽 기준으로 양옆이
  조금 잘립니다.
- **참고 영역 비율 슬라이더 지연:** 1.0.0은 움직임이 멈춘 뒤 180ms를 기다렸다가 다시 그렸습니다. 바로 다시
  그리되 진행 중이면 마지막 값만 남겨 이어서 하게 했습니다. 편집 중인 캔버스는 PNG로 바꾸지 않고 캔버스째
  넘기고(저장할 때만 변환), 마스크 계산을 줄 단위로 바꿨으며(12ms→약 2ms), 화면용 캔버스는 GPU에 둡니다.
  패키징한 앱에서 사용자가 확인했습니다.
- **개발 모드에서만 멈추는 문제:** `npm run dev`에서 슬라이더가 수 초씩 멈추는 것은 React 19.2 개발 모드가
  바뀐 `Uint8Array` prop(마스크)을 원소 하나하나 성능 기록에 남기기 때문입니다. 배포 빌드에는 없으므로 화면
  속도는 패키징한 앱으로 판단합니다.
- **패키징 폴더:** `release/`에는 공개하는 안정 버전만 두고, 확인용 빌드는 `npm run package:test`로
  `release-test/`에 만듭니다.
- **이름과 결과 폴더(2026-10-10):** 「레퍼런스 생성」을 「인페인트」로 바꿨습니다(저장 값은 `reference`
  그대로). 새 결과는 `outputs/<인페인트|일반 생성|i2i|디렉터 툴>/<감정 또는 날짜>/`에 저장합니다.
- **갤러리 선택 버튼:** 일괄 생성 체크(「생성 대상」 모두 체크·해제)와 카드 고르기(「카드」 모두 고르기·
  취소)를 나눴습니다.
- **저장 용량:** 결과·전체 캔버스를 기본으로 WebP 무손실로 저장합니다. 실측 16장 기준 약 41% 작고 픽셀이
  같습니다(PNG 재압축은 약 1%, 손실 WebP 90은 약 10% 크기지만 NovelAI의 알파 채널 메타데이터가 사라짐).
  텍스트 메타데이터는 XMP에 넣고, 불러오기와 PNG 내보내기에서 되살립니다. `inputs/`는 아직 PNG입니다.

## 이어서 할 일

1. 4단계 사용자 확인: i2i 모드·자유 생성 i2i·i2i로 보내기를 무료 범위에서 시험하고 세기 기본값을
   정합니다. 그다음 7단계.
2. `inputs/`(요청 입력)도 WebP 무손실로 줄일지: 보낼 때 PNG로 바꾸는 단계가 필요합니다.
3. 남은 질문: 업스케일의 `model` 값, V5 할당량 소모 방식(i2i가 두 배인지 포함), 배경 제거의 크기별 비용.

## 단계마다 할 일

1. 코드 변경과 테스트(`npm test`, `npm run typecheck`, `npm run lint`)를 통과시킵니다.
2. 실제 NovelAI 호출이 필요한 부분은 실험 도구로 무료 범위에서 확인합니다.
3. 단계 파일의 "결과"와 이 파일의 진행 표를 갱신합니다. 단계 밖에서 한 작업은 위 절에 한 줄씩 적습니다.
4. 로컬 커밋까지만 합니다. 푸시는 사용자 요청이 있을 때만 합니다.
5. 사용자가 릴리스를 요청하면: 버전 올리기 → `CHANGELOG.md` 맨 위 절 작성 → `npm run package:win` →
   사용자 확인 → 사용자가 푸시·릴리스를 요청하면 진행([개발 가이드의 릴리스 절](개발-가이드.md) 참고).
