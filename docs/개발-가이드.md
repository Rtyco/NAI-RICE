# 개발 가이드

NAI RICE의 코드를 읽거나 고치려는 사람을 위한 문서입니다. 기능별 동작, 저장 폴더 구조, 프롬프트가 NovelAI
요청 필드로 들어가는 방식은 [자세한 설명](자세한-설명.md)에 있습니다.

## 빠른 시작

Windows와 Node.js LTS가 필요합니다.

```powershell
npm ci
npm run dev
```

`npm run dev`는 메인 프로세스를 빌드한 뒤, Vite 개발 서버(127.0.0.1:5173)와 Electron을 함께 띄웁니다. 화면
코드(`src/`)는 저장하면 바로 반영되고, `electron/` 코드를 고치면 다시 실행해야 합니다.

> 개발 모드도 실제 `문서\NAI RICE` 폴더와 저장된 토큰을 씁니다. 생성 버튼을 누르면 실제 요청이 나갑니다.

Vite 서버만 브라우저로 열면 `window.referenceDesk`가 없어서, [main.tsx](../src/renderer/main.tsx)가 파일·생성
기능이 빠진 미리보기 API를 대신 넣습니다. 화면 배치만 볼 때 쓸 수 있습니다.

| 명령                       | 하는 일                                                               |
| -------------------------- | --------------------------------------------------------------------- |
| `npm run typecheck`        | `tsc --noEmit`                                                        |
| `npm test`                 | Vitest 한 번 실행 (`npm run test:watch`는 감시 모드)                  |
| `npm run lint`             | ESLint                                                                |
| `npm run format`           | Prettier로 전체 정리 (`format:check`는 검사만)                        |
| `npm run package:portable` | 빌드 후 포터블 실행 파일과 `SHA256SUMS.txt`를 `release/`에            |
| `npm run package:win`      | 빌드 후 설치 파일과 포터블 실행 파일, `SHA256SUMS.txt`를 `release/`에 |

변경을 올리기 전에 `typecheck`, `test`, `lint`를 통과시켜 주세요.

## 구조

```text
화면 (renderer)              preload                    메인 프로세스 (main)
React + zustand        →  contextBridge로         →   electron/ipc.ts의 핸들러
src/renderer/              window.referenceDesk         → electron/services/*
                           하나만 연다                   (파일, NovelAI 요청, 토큰)
            ↘                                          ↙
                  src/core: Electron·DOM과 무관한 규칙
                  (프롬프트 조합, 요청 본문, 캔버스 배치, 검증)
```

- **렌더러는 파일과 네트워크에 직접 손대지 않습니다.** Content Security Policy로 외부 요청을 막고, 이미지는
  저장 폴더 안만 읽는 `desk-media://` 프로토콜로 불러옵니다([window.ts](../electron/window.ts)).
- **메인 프로세스는 렌더러를 믿지 않습니다.** 생성 요청은 zod 스키마로 다시 검사하고, Anlas 경고도 메인
  쪽에서 다시 계산합니다([GenerationRequests.ts](../electron/services/GenerationRequests.ts)).
- **`src/core`는 순수 TypeScript입니다.** 렌더러와 메인 양쪽에서 쓰고, 테스트 대부분이 여기를 대상으로
  합니다.
- **서비스끼리는 [ports.ts](../electron/services/ports.ts)의 작은 인터페이스로 연결합니다.** 실제 구현은
  [main.ts](../electron/main.ts)가 이어 붙이고, 테스트는 필요한 메서드만 가진 가짜 객체를 넘깁니다.

## 생성 한 번의 흐름

1. **작업 만들기 (렌더러)**: [actions.ts](../src/renderer/actions.ts)가 `prepareInputs`로 인페인트의 캔버스와
   마스크를 작업 폴더의 `inputs/<sha256>.png`로 고정한 뒤, `buildJobs`로 감정마다 작업 스냅샷을 만듭니다.
   최종 프롬프트는 `composeRequestPrompts`가 조합하며, 화면의 미리보기도 같은 함수를 씁니다.
2. **검사 (메인)**: `generation:enqueue` → `GenerationRequests`가 스키마 검사와 Anlas 경고를 거쳐 큐에 넣습니다.
3. **생성 (메인)**: [GenerationQueue.ts](../electron/services/GenerationQueue.ts)가 한 번에 하나씩, 정해진
   간격으로 `NovelAIProvider.generate`를 부릅니다. 요청 본문은
   [NovelAIRequestBuilder.ts](../src/core/providers/NovelAIRequestBuilder.ts)가 만듭니다. 요청 제한·서버·
   네트워크 오류는 2·5·10초 뒤 다시 시도하고, 인증·할당량·잘못된 요청은 바로 멈춥니다.
4. **저장 (메인)**: [GenerationOutput.ts](../electron/services/GenerationOutput.ts)가 생성 칸만 잘라 감정별
   폴더에 저장하고 메타데이터를 남긴 뒤, `generations.json`에 기록을 더합니다. 렌더러는 이벤트로 새 기록을
   받습니다.

작업 스냅샷에는 프롬프트, 설정, 입력 파일 해시가 모두 들어 있습니다. 그래서 대기 중에 라이브러리를 고쳐도
이미 넣은 작업은 바뀌지 않습니다. 큐 상태는 저장되어, 앱을 다시 켜면 대기 중이던 작업이 일시 정지 상태로
남습니다.

## 자주 하는 변경

### 설정 칸 하나 추가

라이브러리에 저장되는 값은 네 곳이 맞아야 합니다.

1. `src/core/domain/types.ts`: 타입에 필드 추가
2. `src/core/validation/schemas.ts`: 스키마에 추가. 예전 파일에는 이 값이 없으므로 `.default(...)`를 둡니다.
3. `src/core/model/defaults.ts`: 새로 만들 때의 값
4. 화면: 생성 설정이면 `views/LibraryView.tsx`, 프로그램 설정이면 `views/SettingsModal.tsx`

요청에 들어가는 값이면 `NovelAIRequestBuilder.ts`와 그 테스트도 고칩니다. 저장 형식을 호환되지 않게 바꿀
때만 `schemaVersion`을 올리고 `src/core/backup/Migration.ts`에 옮기는 코드를 더합니다.

### IPC 하나 추가

1. `src/shared/ipc.ts`: 해당 기능 API 타입(`LibraryApi`, `AppApi` 등)에 메서드 추가
2. `electron/ipc.ts`: `ipcMain.handle('영역:동작', ...)`. 렌더러에서 온 값은 스키마로 검사합니다.
3. `electron/preload.ts`: `ipcRenderer.invoke`로 연결
4. `src/renderer/main.tsx`의 미리보기 API에 빈 구현 추가 (타입 검사가 알려 줍니다)
5. 렌더러는 `window.referenceDesk` 대신 [desktop.ts](../src/renderer/desktop.ts)의 `libraryApi()` 같은 함수로
   씁니다.

외부로 나가는 동작(브라우저 열기 등)은 메인에서 주소를 검사합니다. 업데이트 창의 링크는 `https://github.com/`
주소만 엽니다.

### NovelAI 모델이나 태그

모델 목록, 품질 태그, UC 프리셋 문구는 [NaiModels.ts](../src/core/providers/NaiModels.ts)에 있습니다. 요청
본문의 버전별 차이(V3, V4·V4.5, V5)는 `NovelAIRequestBuilder.ts`에 모여 있고, 테스트가 실제 요청 모양을
고정해 둡니다.

## 테스트

- `tests/unit`: `src/core`와 서비스 단위 테스트. 서비스는 `ports.ts` 인터페이스에 맞춘 가짜 객체로 시험합니다.
- `tests/integration`: 임시 폴더에서 라이브러리 이전, 저장 공간 정리, 생성 파이프라인을 끝까지 돌립니다.
  NovelAI 호출은 가짜로 바꿉니다.
- 실제 NovelAI에 요청하는 테스트는 없습니다.
- `greatOathFixtures.test.ts`는 외부 샘플 폴더(`GREAT_OATH_NOTES` 환경 변수)가 있을 때만 돌고, 없으면
  건너뜁니다.

## 릴리스

1. `package.json`과 `package-lock.json`의 버전을 올립니다.
2. `CHANGELOG.md` 맨 위에 새 버전 항목을 씁니다. 이 항목이 GitHub 릴리스 노트가 되고, 앱의 업데이트 알림
   창에도 그대로 보입니다.
3. `npm run package:win`으로 `release/`에 설치 파일, 포터블 파일, `SHA256SUMS.txt`를 만듭니다.
4. `v<버전>` 태그로 GitHub 릴리스를 만들고 세 파일을 올립니다.

앱의 업데이트 확인([UpdateCheck.ts](../src/core/update/UpdateCheck.ts))은 이 저장소의 `releases/latest`를
읽고, 파일 이름이 `-setup.exe`나 `-portable.exe`로 끝나는 첨부 파일을 찾습니다. 파일 이름 규칙은
`electron-builder.yml`의 `artifactName`을 따르니 바꾸지 마세요.

## 자주 만나는 문제

| 증상                                            | 해결                                                                                                    |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `npm run dev`가 창 없이 Node처럼 실행됨         | 환경 변수 `ELECTRON_RUN_AS_NODE`가 켜져 있습니다. PowerShell에서 `Remove-Item Env:ELECTRON_RUN_AS_NODE` |
| 패키징 중 `EBUSY` (`win-unpacked\NAI RICE.exe`) | 그 폴더의 앱이 실행 중이거나 잠깐 잠긴 것입니다. 앱을 끄고 다시 실행합니다                              |
| 앱이 `library.json`을 읽지 못함                 | 타입·스키마·기본값이 서로 맞지 않는 경우가 많습니다. 원본은 `문서\NAI RICE\backups`에 있습니다          |
