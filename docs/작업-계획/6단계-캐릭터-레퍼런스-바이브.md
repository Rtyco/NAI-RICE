# 6단계: 캐릭터 레퍼런스·바이브 트랜스퍼 (대기)

## 0단계에서 확인한 것

- **V4.5 전용입니다.** V5로 보내면 V4.5로 바뀌지 않고 **500 오류**가 납니다(캐릭터 레퍼런스, V4.5 인코딩
  바이브 모두 5번 시도). 500을 다시 시도한 요청은 차감이 없었습니다.
- **캐릭터 레퍼런스:** 무료 조건 안에서도 한 번에 **5 Anlas**. 참고 그림의 머리·옷이 잘 옮겨집니다. 요청 필드:
  - `director_reference_images`: 1024×1536 등 정해진 캔버스에 검은 여백을 넣은 그림
  - `director_reference_descriptions`: `base_caption: "character&style"` 또는 `"character"`
  - `director_reference_information_extracted: [1]`, `director_reference_strength_values: [1]`
  - `director_reference_secondary_strength_values: [1 - fidelity]`
- **바이브:** `POST https://image.novelai.net/ai/encode-vibe`, 본문 `{ image, information_extracted, model }`.
  인코딩 한 번에 **2 Anlas**, 응답은 `application/binary`(ZIP 아님, 약 49KB). 같은 모델에서 다시 써도 추가
  차감이 없습니다. 생성 요청에는 `reference_image_multiple: [인코딩 결과 base64]`,
  `reference_strength_multiple`, `normalize_reference_strength_multiple: true`를 넣습니다.
- **인셋 + 바이브(V4.5 인페인트)는 됩니다.** 캐릭터 레퍼런스와 바이브를 함께 쓸 수 있는지는 확인하지
  않았습니다(커뮤니티 구현은 함께 쓸 수 없다고 봄).
- 비용 계산: 캐릭터 레퍼런스가 있으면 장당 +5(`NaiCost.ts`의 계산식에 반영 필요).

## 할 일

- 레퍼런스 생성 모드 안에 방식 선택을 둡니다: **인셋(지금 방식) / 캐릭터 레퍼런스 / 바이브 / 인셋 +
  바이브**.
- 캐릭터 레퍼런스·바이브는 V4.5 전용이라고 화면에 분명히 표시하고, V5를 고르면 막거나 바꾸게 합니다.
- 바이브는 인코딩 결과를 저장해 두고 재사용해 인코딩 비용을 한 번만 냅니다.
- 라이브러리의 「인페인트」 항목을 "참고 이미지" 개념으로 넓혀, 같은 그림을 인셋·캐릭터 레퍼런스·바이브
  어디서든 쓰게 합니다. 이름 변경과 데이터 이전은 2단계 호환 방식(zod 기본값 + 옛 데이터 테스트)으로
  처리합니다.
