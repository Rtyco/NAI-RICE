# 6단계: 캐릭터 레퍼런스·바이브 트랜스퍼 (구현, 사용자 확인 전)

## 0단계에서 확인한 것

- **V4.5 전용입니다.** V5로 보내면 V4.5로 바뀌지 않고 **500 오류**가 납니다(캐릭터 레퍼런스, V4.5 인코딩
  바이브 모두 5번 시도). 500을 다시 시도한 요청은 차감이 없었습니다.
- **캐릭터 레퍼런스:** 무료 조건 안에서도 한 번에 **5 Anlas**. 참고 그림의 머리·옷이 잘 옮겨집니다. 요청 필드:
  - `director_reference_images`: 1024×1536 등 정해진 캔버스에 검은 여백을 넣은 그림
  - `director_reference_descriptions`: `base_caption: "character&style"` 또는 `"character"`
  - `director_reference_information_extracted: [1]`, `director_reference_strength_values: [1]`
  - `director_reference_secondary_strength_values: [1 - fidelity]`
- **바이브:** `POST https://image.novelai.net/ai/encode-vibe`, 본문 `{ image, information_extracted, model }`.
  인코딩 한 번에 **2 Anlas**, 응답은 `application/binary`(ZIP 아님, 약 49KB). 같은 모델에서 다시 써도 추가
  차감이 없습니다. 생성 요청에는 `reference_image_multiple: [인코딩 결과 base64]`,
  `reference_strength_multiple`, `normalize_reference_strength_multiple: true`를 넣습니다.
- **인셋 + 바이브(V4.5 인페인트)는 됩니다.** 캐릭터 레퍼런스와 바이브를 함께 쓸 수 있는지는 확인하지
  않았습니다(커뮤니티 구현은 함께 쓸 수 없다고 봄).
- 비용 계산: 캐릭터 레퍼런스가 있으면 장당 +5(`NaiCost.ts`의 계산식에 반영 필요).

## 할 일

- 레퍼런스 생성 모드 안에 방식 선택을 둡니다: **인셋(지금 방식) / 캐릭터 레퍼런스 / 바이브 / 인셋 +
  바이브**.
- 캐릭터 레퍼런스·바이브는 V4.5 전용이라고 화면에 분명히 표시하고, V5를 고르면 막거나 바꾸게 합니다.
- 바이브는 인코딩 결과를 저장해 두고 재사용해 인코딩 비용을 한 번만 냅니다.
- 라이브러리의 「인페인트」 항목을 "참고 이미지" 개념으로 넓혀, 같은 그림을 인셋·캐릭터 레퍼런스·바이브
  어디서든 쓰게 합니다. 이름 변경과 데이터 이전은 2단계 호환 방식(zod 기본값 + 옛 데이터 테스트)으로
  처리합니다.

## 결과

2026-10-12에 구현했습니다. 실제 요청은 유료(캐릭터 레퍼런스 한 장 5, 바이브 인코딩 2 Anlas)라 사용자 확인이
남았습니다.

- **방식 나누기(계획에서 바꾼 것):** 「인페인트 모드 안의 방식 네 가지」 대신, 작업에서 캐릭터 레퍼런스나 바이브를
  하나 골라 모드(인페인트·일반 생성)와 조합합니다. NovelAI에서 바이브는 생성·인페인트 어디에나
  더하는 값이고, 캐릭터 레퍼런스는 일반 생성에 더하는 값이라 이쪽이 실제 동작과 맞습니다. 계획의 네 방식은
  다음과 같습니다.
  - 인셋: 인페인트 + 참고 없음(지금 그대로)
  - 캐릭터 레퍼런스: 일반 생성 + 캐릭터 레퍼런스
  - 바이브: 일반 생성 + 바이브
  - 인셋 + 바이브: 인페인트 + 바이브
  - 인페인트 + 캐릭터 레퍼런스는 확인하지 않아 고를 수 없게 했습니다. 캐릭터 레퍼런스와 바이브를 함께 쓰는 것도
    (커뮤니티 구현은 안 된다고 봄) 하나만 고르게 했습니다.
- **라이브러리 항목(사용자 요청, 2026-10-12):** 처음에는 인페인트 항목의 원본 그림과 작업의 「참고」 창을 썼으나,
  라이브러리에 **캐릭터 레퍼런스**(F7)·**바이브**(F8) 칸을 따로 두었습니다. 항목마다 그림과 값(충실도·Style
  Aware, 세기·정보 추출)을 담고, 작업은 구성 막대의 칩으로 하나를 고릅니다(`Project.characterReferenceId`,
  `Project.vibeId`). 둘을 함께 고르지 않게 하나를 고르면 다른 하나를 끕니다.
- **그림 저장:** `pictures/<내용 해시 24자>.png`. 같은 그림은 한 파일이고, 복제한 항목도 같은 파일을 씁니다. 전체
  백업에 그림을 data URL로 넣고, 가져오면 같은 이름으로 다시 저장되어 항목이 그대로 가리킵니다. 그림을 JSON에
  넣지 않아 항목 하나씩 내보내기는 두지 않았습니다.
- **작업이 지워진 항목을 가리키면:** 경고 띠에 「캐릭터 레퍼런스」·「바이브」, 그림이 없으면 「… 그림」이 나옵니다.
  항목을 지울 때 대신할 항목을 고르지 않으면 작업의 연결을 뺍니다(참고 없이 생성).
- **V4.5 전용:** `supportsReferenceAid`(V4.5 Full·Curated). 다른 모델이면 칩이 주황색이 되고 경고 띠에 「V4.5
  모델」이 나오며, 작업을 만들 때도 막습니다.
- **캐릭터 레퍼런스:** 그림을 세로 1024×1536, 가로 1536×1024, 정사각 1472×1472 중 비율이 가까운 캔버스에
  검은 여백으로 맞춰 `inputs/`에 넣습니다(`fitCharacterReference`). 요청은 0단계 형식 그대로이고, Style Aware를
  끄면 `base_caption: "character"`, 충실도는 `secondary_strength = 1 - 충실도`입니다. 비용 계산에 장마다 +5.
- **바이브:** 그림을 `inputs/`에 넣고, 큐가 생성 직전에 인코딩합니다. 결과는 작업 폴더 밖
  `vibes/<그림 해시>-<모델>-ie<추출량>.bin`에 두고 다음부터 다시 써 인코딩 비용(2 Anlas)을 한 번만 냅니다.
  인코딩은 일반 생성 모델 ID로 하고, 인셋 + 바이브의 인페인트 요청에도 그 결과를 넣습니다(0단계와 같음). 큐에 넣을 때 아직
  인코딩하지 않은 바이브가 있으면 2 Anlas를 예상에 더해 묻습니다.
- **결과 기록:** `aid`(방식·항목 이름·값)를 남기고, 생성 정보에 「참고 방식」으로 보여 줍니다.

### 사용자 확인 (유료)

`npm run dev`에서 라이브러리에 캐릭터 레퍼런스·바이브 항목을 하나씩 만들고(그림 불러오기), 생성 설정을 V4.5
Full로, 씬 하나·장수 1로 시험합니다.

1. 일반 생성 + 캐릭터 레퍼런스 한 장(5 Anlas): 참고 그림의 캐릭터가 옮겨지는지. 가능하면 Style Aware를 끈 것과
   충실도를 낮춘 것도 한 장씩.
2. 일반 생성 + 바이브 한 장: 처음에 인코딩 2 Anlas를 묻는지, 두 번째 생성에서는 묻지 않는지(`vibes/`에 파일이
   생기는지).
3. 인페인트 + 바이브 한 장: 인셋과 함께 되는지.
