# 3단계: 일반 생성과 자유 생성 화면 (완료)

끝난 단계입니다. 지금 동작은 아래 「결과」를 보고, 그 앞의 절은 시작할 때의 기록으로 남겨 둡니다. 화면 문구의
「감정」은 2026-10-10부터 「씬」이고, 「레퍼런스 생성」은 「인페인트」입니다(코드 이름은 그대로).

## 시작할 때의 구조 (2단계 이후)

[개발 가이드](../개발-가이드.md)의 "생성 한 번의 흐름"과 함께 봅니다.

- **작업 종류는 이미 있습니다.** `GenerationJobSnapshot`은 `kind`(`inpaint`·`txt2img`·`img2img`·`augment`)로
  나뉘는 합 타입이고(`src/core/domain/types.ts`), 큐·요청·저장이 모두 종류를 따릅니다. 텍스트만으로 만드는
  작업은 `Txt2ImgJobSnapshot`(입력 이미지 없음)입니다.
- **아직 인페인트 작업만 만들어집니다.** 렌더러의 `generateEmotions`(`src/renderer/actions.ts`)가 입력
  이미지를 준비하고 `buildJobs`(`src/core/jobs/JobBuilder.ts`)로 `InpaintJobSnapshot`만 만듭니다. txt2img용
  작업 생성 함수를 새로 넣어야 합니다. 프롬프트 합성 `composeRequestPrompts`는 그대로 씁니다.
- 메인 프로세스의 `GenerationRequests`는 종류와 무관하게 스키마 검증·비용 확인·큐 넣기를 합니다.
  `GenerationQueue.loadInputs`는 txt2img면 입력을 읽지 않습니다.
- **저장:** `GenerationOutput`은 인페인트만 `outputRect`로 자르고, 나머지는 받은 PNG를 그대로 저장합니다.
  저장 위치는 `store.emotionOutputDir(projectId, emotionName)`(감정 폴더)이고 기록은 감정 ID를 필수로
  가집니다. 자유 생성은 감정이 없으므로 저장 위치와 `emotionId`를 정해야 합니다.
- **모델:** `NaiModels.ts`의 모델마다 `requestIds: { inpaint?, generate }`가 있고, 저장 값은 인페인트 모델
  ID입니다. 생성 설정의 모델 선택은 `INPAINT_MODELS`만 보여 줍니다. V5 Curated(`nai-diffusion-5-curated`)는
  일반 생성 전용이라 아직 목록에 없습니다.
- **작업(`Project`)** 은 `presetId`·`characterId`·`promptSetId`·`emotionSetId`·`referenceId`를 묶습니다.
  모드 필드는 없습니다. 생성 결과는 `generations.json`에 감정별로 쌓입니다.
- **비용:** `estimateJobAnlas`, `generationCostWarnings`(`NaiCost.ts`)가 txt2img도 계산합니다. 1024×1024
  이하·28스텝 이하·Opus면 무료입니다.

## 0단계에서 확인한 것

- **일반 생성 모델 ID:** `nai-diffusion-5-full`, `nai-diffusion-5-curated`, `nai-diffusion-4-5-full`,
  `nai-diffusion-4-5-curated`, `nai-diffusion-4-full`, `nai-diffusion-4-curated-preview`, `nai-diffusion-3`이 모두
  됩니다.
- 응답은 인페인트와 같은 ZIP(`image_0.png`, RGBA)입니다. 일반 결과도 알파 최솟값이 243~254라, 투명 여부는
  "알파 최솟값이 0인가"로 판단합니다.
- V5 `transparent background` 태그로 일반 생성하면 배경이 실제로 투명합니다(알파 0).
- 요청 본문은 2단계의 `buildNovelAIDiffusionRequest`가 이미 맞게 만듭니다(0단계 성공 요청과 같음).

## 3-1. 모드 버튼

- 작업 화면 위에 **[레퍼런스 생성] [일반 생성]** 버튼을 둡니다. 작업마다 모드를 저장합니다
  (`Project.mode`, 기본값 `reference`). 옛 데이터는 모드가 없으면 `reference`로 읽습니다(zod 기본값 + 테스트).
- **레퍼런스 생성:** 지금의 인셋(인페인트) 방식입니다. 6단계에서 캐릭터 레퍼런스·바이브가 이 모드에
  들어옵니다.
- **일반 생성:** 인페인트 없이 생성 설정 + 캐릭터 + 감정 모음으로 txt2img를 합니다. 작업 구성 막대에서
  인페인트 칸을 숨기고, 해상도는 생성 설정에서 고릅니다(무료 해상도 프리셋 + 직접 입력).
- 감정 갤러리, 대표 이미지, 감정 상세, 내보내기는 두 모드가 같이 씁니다.
- 일반 생성 모델 목록에 V5 Curated를 넣습니다. 인페인트 모델 목록에는 넣지 않습니다.

## 3-2. 자유 생성 화면

감정 구조 없이 프롬프트만으로 여러 장 뽑는 화면입니다. 사용자가 감정 모드와 따로 두기로 했습니다.

- 사이드바에 「자유 생성」 항목을 따로 둡니다(작업 목록과 구분).
- 화면 구성: 생성 설정 선택, 캐릭터 선택(선택 사항), 프롬프트 입력, 해상도, 장수, 생성 버튼, 결과 격자.
- 결과는 감정이 아니라 생성 순서로 쌓입니다. 결과마다 다시 생성(같은 seed), 프롬프트 복원, 생성 정보,
  삭제, 다른 이름으로 저장, 그리고 4·5단계가 붙으면 i2i·디렉터 툴로 보내기를 제공합니다.
- 저장 위치: 작업 폴더 안의 별도 폴더(예: `free/<세션 또는 날짜>/`). 결과 기록 형식은 `GenerationRecord`를
  재사용하고 `emotionId`는 비워 둡니다.
- 생성 방식은 txt2img 기본, 4단계 이후 i2i도 고를 수 있게 합니다.

## 결과

### 3-1 (2026-10-10)

- `Project.mode`(`reference`·`txt2img`)를 넣고, 옛 작업은 `reference`로 읽습니다. 작업 이름 옆의
  [레퍼런스 생성] [일반 생성] 버튼으로 바꿉니다. 일반 생성에서는 구성 막대의 인페인트 칸 대신 해상도를
  보여 주고, 누르면 생성 설정으로 갑니다. 고른 인페인트(`referenceId`)는 모드를 되돌릴 때를 위해 남겨 둡니다.
- 해상도는 `GenerationSettings.width`·`height`(기본 832×1216, 256~2048, 64의 배수)입니다. 생성 설정의
  「일반 생성 해상도」에서 무료 프리셋 셋이나 직접 입력으로 고릅니다. 레퍼런스 생성은 계속 인페인트의
  캔버스 크기를 씁니다.
- 작업은 `buildTxt2ImgJobs`가 만들고, 인페인트와 감정·seed·프롬프트 처리를 같이 씁니다. reference inset
  태그는 인페인트에만 붙입니다(미리보기도 같음). 결과는 `outputs/일반 생성/<씬>/`에 저장되고(방식별 폴더,
  인페인트는 `outputs/인페인트/<씬>/`), 생성 정보에 「방식」이 보입니다.
- 모드 버튼은 지금 [인페인트] [일반 생성]입니다. 생성 버튼과 생성할 씬·씬마다 장수·예상 Anlas는 아래 생성 큐
  막대 오른쪽에 있습니다(작업 계획 개요의 「비슷한 일끼리 묶기」).
- **V5 Curated:** 모델 목록에 넣었습니다(저장 값 `nai-diffusion-5-curated`, 일반 생성 전용). NovelAI 웹
  코드(2026-10)를 확인한 결과 품질 태그·UC 프리셋은 V5 Full과 같고, nsfw를 자동으로 붙이지 않습니다. 웹도
  V5 Curated 인페인트는 V4.5 Curated 인페인트 모델로 보내므로 인페인트 목록에는 넣지 않았습니다. 레퍼런스
  생성 작업에서 이 모델을 고르면 "인페인트 모델"이 필요하다고 알리고 생성을 막습니다.
- 생성 설정은 두 모드가 함께 쓰므로 모델 목록은 하나입니다. 일반 생성 전용 모델에는 "(일반 생성 전용)"을
  붙였습니다.
- 사용자가 일반 생성을 실제로 실행해 문제없음을 확인했습니다.

### 3-2 (2026-10-10)

- 사이드바 맨 위 「자유 생성」. 결과는 작업과 따로 `projects/free/`에 쌓입니다(사용자 결정). 작업 ID는 항상
  무작위 접미사가 붙어 `free`와 겹치지 않습니다. 생성 기록·썸네일·삭제·저장 공간 화면(「자유 생성」 줄)은
  작업과 같은 코드를 씁니다.
- 결과 파일은 `outputs/<일반 생성|i2i|인페인트>/<YYYY-MM-DD>/<날짜>-<시각>__<seed>.webp`(현지 날짜 폴더,
  확장자는 저장 형식 설정을 따르며 기본은 WebP 무손실)입니다. 이 구분 전의 결과는 `outputs/<YYYY-MM-DD>/`에 남아 있습니다. 씬이 없으므로 설정의
  파일명 규칙은 쓰지 않습니다.
- 화면: 위쪽 [일반 생성 | i2i] 버튼과 생성 설정·캐릭터(없음 가능)·해상도 칩. 가운데는 씬 상세와 같은 큰
  미리보기, 그 아래 「선택한 결과」 막대(`ResultBar`), 필름 스트립(여러 장 선택·삭제)입니다. 오른쪽은
  프롬프트와 붙일 위치, 아래에 붙은 장수(1~20)·예상 Anlas·생성 버튼입니다. 결과에 하는 일(이 seed로 다시,
  프롬프트 복원, i2i로 보내기·자유 생성 i2i·인페인트 만들기, 저장, 폴더에서 보기, 삭제)은 막대와 이미지
  우클릭 메뉴가 같은 목록을 쓰고, 생성 정보는 막대의 ⓘ로 엽니다. 마지막 입력값은
  `Library.freeGeneration`에 저장합니다.
- 입력한 프롬프트는 처음에 공통 포지티브 끝에만 붙였는데(장면·구도 설명이 많아서), 지금은 생성 설정과 같은
  두 위치(공통 포지티브 맨 끝·캐릭터 프롬프트 맨 끝) 중에서 고릅니다(`FreeGeneration.promptPosition`, 기본
  공통 끝, 캐릭터 프롬프트가 없으면 공통 끝). 기록의 `emotionPrompt`에 남아 프롬프트 복원에 씁니다.
  `emotionId`는 비어 있습니다.
- 한 장씩 따로 요청해 Opus 무료 범위를 지킵니다.
- i2i(전체 다시 그리기·인페인팅)는 4단계에서 붙였습니다. 디렉터 툴로 보내기는 5단계에서 붙입니다.
- 일반 생성 작업의 해상도 칩은 다른 칩처럼 목록에서 고릅니다(생성 설정 편집은 생성 설정 칩의 고르기 창에서).
  해상도는 생성 설정에 저장되므로 같은 생성 설정을 쓰는 작업·자유 생성에 함께 반영됩니다.
